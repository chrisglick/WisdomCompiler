### 3. Mobile CSS Overhaul (`quartz/styles/custom.scss`)

- **Problem:** Text did not wrap on iPhone SE 2020 (375px viewport). User reported it appeared as if a `min-width: 800px` was forcing the page wide.
- **Analysis:** `$mobile` breakpoint is `max-width: 800px` in `variables.scss`. No pixel-based `min-width` on layout containers, but missing overflow and word-break rules allowed content to push containers wider.
- **Fixes added** (all scoped inside `@media all and ($mobile)`):
  - `html, body, .page`: `overflow-x: hidden; max-width: 100vw`
  - `.page > #quartz-body .center`: `overflow-x: hidden; max-width: 100%; word-wrap: break-word; overflow-wrap: break-word`
  - `article`: `max-width: 100%; overflow-wrap: break-word; word-break: break-word`
  - `article a`: `word-break: break-word; overflow-wrap: break-word`
  - `article img`: `max-width: 100%; height: auto`
  - `.table-container`: `overflow-x: auto` (added alongside existing `max-width: 100%`)
  - `pre`: `overflow-x: auto` (added alongside existing `max-width`)
- **Desktop impact:** None — all rules scoped to mobile media query.

## Key Technical Details

### Quartz Wikilink Resolution Gotcha

`[[FolderName/|Display Text]]` resolves to a FILE named `FolderName.md` inside the folder if one exists, NOT to the folder's auto-generated index page. This causes 404s when the file is draft. Solution: either delete the colliding file or rename it to `index.md` (which Quartz uses as the folder's custom page).

### Mobile CSS Architecture

All mobile rules in `custom.scss` are inside `@media all and ($mobile)` where `$mobile = "(max-width: 800px)"`. The key to preventing horizontal scroll on narrow viewports is the combination of:
1. `overflow-x: hidden` on html/body/.page (prevents scrollbar)
2. `max-width: 100vw` on body/.page (constrains width)
3. `word-break: break-word` on article/links (wraps long text)
